# Use of AI

Space Apps 2026 asks every project to declare how AI was used. This file is updated
as the project goes.

## Who decided what

The approach, the architecture and every data decision were made by the team members
(Lautaro Cena and Máximo Galizia). The AI assistant researched, wrote code, reviewed
and proposed; it did not choose how to solve the challenge.

## Data

- No data was generated by AI. All data comes from NASA PSI (CC0-1.0).
- Every correction to the data is listed in `Backend/pipeline/mappings/decisions.csv`
  and is only applied once a team member approves it. Until then the affected rows are
  flagged `pending:<decision>` and keep their original value.
- Outcomes derived by rules (for example, from operator notes in BASS-II) are marked
  `outcome_status = provisional` in the database.

## AI inside the product

- **Interpretable models** (logistic regression and Cox survival models, stored as JSON,
  `flame/`, `models/`) estimate probabilities. They answer only where NASA ran clean tests
  with the same combination of conditions; elsewhere they say "no data" and why.
- **Document search**: reports are split into pages and embedded with an open-source
  embedding model (`BAAI/bge-small-en-v1.5`); a hybrid search (vector + full text + rank
  fusion) finds the passages. Chunks that are mostly numbers (tables) are left out: those
  numbers come from the curated tables instead. It only finds text; it does not write.
- **Assistant (language model)**: an open-source language model run by the team writes the
  chat answer **only from what the tools return** (the models, the curated NASA tables and
  the retrieved report passages). It labels each answer as answer / partial / not enough
  data, cites its sources, and a verifier checks that every number in the text appears in a
  tool output. It never receives database credentials and never writes SQL. The UI shows
  the tools used and the verifier result for each answer ("See how it was answered").
- If the assistant is not available, the chat answers with a fixed template built from the
  same models, marked as a partial answer.
- Details of the services: `docs/SERVICES.md`.
