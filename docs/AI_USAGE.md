# Use of AI

Space Apps 2026 asks every project to declare how AI was used. This file is updated
as the project goes.

## Who decided what

The approach, the architecture and every data decision were made by the team members
(Lautaro Cena and Máximo Galizia). The AI assistant researched, wrote code, reviewed
and proposed; it did not choose how to solve the challenge.

## Code written with an AI assistant

Claude (Anthropic), used through Claude Code, helped write:

| Part | Files |
|---|---|
| Data pipeline for the PSI CSV files (ingestion, typing, mapping, loading) | `Backend/pipeline/` |
| Database schema and views | `Backend/sql/`, `RAG/sql/` |
| Backend API, service clients and placeholder model functions | `Backend/api/` |

| Dashboard | `Frontend/` |

Commits made with the assistant carry a `Co-Authored-By` line.

## Data

- No data was generated by AI. All data comes from NASA PSI (CC0-1.0).
- Every correction to the data is listed in `Backend/pipeline/mappings/decisions.csv`
  and is only applied once a team member approves it. Until then the affected rows are
  flagged `pending:<decision>` and keep their original value.
- Outcomes derived by rules (for example, from operator notes in BASS-II) are marked
  `outcome_status = provisional` in the database.

## AI inside the product

- The answers in "Ask the data" are built from templates over the numbers returned by
  the backend. No language model writes them.
- An LLM service may optionally be used **only** to translate a question into
  structured conditions when the built-in parser fails (decision D2). It never sees
  the data. See `docs/SERVICES.md`.
- The current model functions in `Backend/api/modeling.py` are **placeholders**
  (nearest-neighbour baseline). They will be replaced by the interpretable models.
