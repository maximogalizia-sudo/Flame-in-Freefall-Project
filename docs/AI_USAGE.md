# Use of AI

Space Apps 2026 asks every project to declare how AI was used. This file is updated
as the project goes.

## Who decided what

The approach, the architecture and every data decision were made by the team members
(Lautaro Cena and Máximo Galizia). The AI assistant researched, wrote code, reviewed
and proposed; it did not choose how to solve the challenge. Each data decision is logged
with who took it (`DD-001`…`DD-033`, team decision log).

## Data

- No data was generated by AI. All data comes from NASA PSI (CC0-1.0) and NASA technical reports.
- Every correction or interpretation of the data is a recorded team decision; the original values are kept.
- Some outcomes exist only as free text in NASA logs (BASS, BASS-II). They were coded with
  **explicit rules written by the team (regular expressions, no language model)**, checked by
  hand on a random sample (28 of 29 agree), and the original NASA text is always shown next to
  the code. These outcomes are used as evidence, not to train a model.

## AI inside the product

- **Interpretable models** (regularized logistic regression and Cox survival models, stored as
  JSON coefficients in `models/`, code in `flame/`) estimate probabilities. They give a number
  only where NASA ran clean tests with the same combination of conditions; elsewhere they say
  "no data", why, and which real tests are closest. The **early-warning risk indicator**, the
  **scenario explorer** and the **per-variable explanations** are computed from these same
  models and data (`flame/scenarios.py`); untested combinations are shown as "unknown" (gray),
  never as safe.
- **Document search**: NASA reports are split into passages and embedded with a small
  open-source embedding model (`BAAI/bge-small-en-v1.5`); a hybrid search (vector + full text +
  rank fusion) finds the passages. It only finds text; it does not write.
- **Assistant (language model)**: an **open-weight language model** (Qwen `qwen3.8-27b`, with
  OpenAI `gpt-oss-120b` / `gpt-oss-20b` as fallbacks) **hosted by Groq** (third-party API) is used
  for two things only:
  1. to turn a Spanish question into a short English search query for the reports (the index is English);
  2. to write the chat answer **only from what the tools return** (models, curated NASA tables,
     retrieved report passages).
  What is sent to the provider: the user's question and the tool outputs (public NASA data);
  no personal data, no database access. The question is understood and routed to the tools by
  **rules written by the team**, not by the language model.
- **Verifier**: every drafted answer is checked before it is shown: every number must appear in a
  tool output, every citation must exist, no fuel or material may be named that the tools did
  not return, and the answer / partial / not-enough-data label must match the evidence. If any
  check fails, or the language model is not available, the answer is built from fixed templates
  with the same data (marked in the trace). The UI shows the tools used and the verifier result
  ("See how it was answered").
- **Evaluation**: a bank of questions written by the team (`assistant/bench/`) measures intent,
  tool choice, abstention and invented numbers (target: zero).
- The language model can be swapped for a locally run open model (e.g. Ollama) by changing one
  environment variable; no code change.
